# ONai: паттерны динамической объектной анимации

Эта библиотека нужна для Reels, в которых смысл объясняется объектами, а аватар лишь сопровождает рассказ. Основа получена из покадрового разбора Pronin Media `Da5UCrPMq7H`, но визуальный язык, бренд-код и реализация принадлежат ONai.

## 1. Semantic inheritance

Следующая сцена наследует хотя бы один объект из предыдущей. Карточка не исчезает в пустоту: она уменьшается, перемещается, раскрывается или становится частью новой схемы. Это сохраняет причинную связь и снижает ощущение слайд-шоу.

## 2. Draw → travel → resolve

Сначала рисуется линия, затем по ней идёт пакет/частица, затем узел меняет состояние. Если нет третьего шага, движение декоративное. Подходит для API, сервера, авторизации, БД, платежей и автоматизаций.

## 3. Object assembly

Сложный объект собирается слоями: корпус → подпись → активная область → результат. Примеры: интерфейс браузера, карта проекта, чек, документ, терминал. Входы смещаются на `4–10 кадров`, чтобы зритель успевал считывать причинность.

## 4. State transformation

Один объект проходит три состояния: исходное → обработка → результат. Цвет результата появляется только после действия. В ролике №6: `окно POST /api с ошибкой 500 → диагностическая линза / ПОЧЕМУ? → сохранённая карточка 500 API→SERVER / +1 КЕЙС`.

## 5. Scanner / proof motion

Скан-линия, курсор, рамка выбора или печатающаяся строка показывают, куда смотреть в реальном интерфейсе. Это доказательный приём, не HUD-декор: он разрешён только когда действительно проверяет файл, блок или значение.

## 6. Particle transfer

Несколько маленьких семантических тегов переносят состояние между двумя объектами: `симптом → причина → исправление → проверка`. Они должны собираться в понятный результат, а не существовать как декоративные осколки. Использовать до четырёх элементов; больше выглядит как AI-slop.

## 7. Accumulation map

Паттерны, ошибки или навыки накапливаются в дорожку, стек или кластер. Новая сущность не заменяет старую, а дополняет систему. Подходит для прогресса, чек-листов, стека технологий и серии шагов.

## 8. Contrast gate

Красный блок физически не проходит через проверку; зелёный получает право двигаться дальше. Подходит для безопасности, права, деплоя, валидации и платежей. Запрещены фальшивые проценты, таймеры и псевдотехнические шкалы.

## 9. Evidence window

Реальный скриншот, запись сайта, код или документ занимает большую часть рабочей зоны. Внутри разрешены зум, панорамирование, подсветка и курсор. Нельзя заменять работающий интерфейс статичной картинкой, если речь идёт о процессе.

## 10. Narrator choreography

Аватар не заполняет ролик постоянно. Состояния: `absent`, `mini-left`, `mini-right`, `personal-hero`, `cta-emphasis`. В каждой сцене сначала выбирается смысловой объект, затем свободное место для головы. Большой план допускается только на личном признании или призыве.

## 11. Kinetic text as a seam

Основные субтитры статичны по шрифту и геометрии. Дополнительное курсивное слово может жить в блоке анимации. Оно не дублирует всю фразу, а формулирует вывод: «проект за проектом», «причина найдена».

## 12. Resource-aware ladder

Приоритет реализации:

1. HTML/CSS/SVG/GSAP — бесплатно по генеративным токенам, полностью редактируется.
2. Официальный SVG/PNG бренда — скачивается один раз, кэшируется с источником.
3. Реальная запись интерфейса — дороже по диску, но сильнее как доказательство.
4. Локальный puppet/render — CPU-операция, генеративных токенов не требует.
5. Image generation — только для уникального персонажа или предмета, который нельзя честно собрать кодом.

## 13. AI-generation semantic gate

- Объект должен узнаваться без подписи максимум за `0,5 с`.
- Если один и тот же предмет можно без потери смысла назвать «AI», «энергией», «данными» или «знаниями», он отклоняется.
- Болты, неон, стекло, трубы и свечение не заменяют смысл.
- Идентичность объекта сохраняется в переходе: меняются состояние и положение, а не весь дизайн.
- Логотипы компаний берутся только из официальных SVG/PNG; генерация логотипов запрещена.
- Генерируются отдельные предметы на прозрачном фоне — без текста, проводов и интерфейса, запечённых внутрь PNG.
- Перед интеграцией проходят три проверки: смысловая читаемость, визуальный AI-slop, пригодность к анимации.

## 14. Publish-safe composition

- Финальный холст остаётся `1080×1920`; безопасная рамка не достигается уменьшением экспортного файла.
- Для экспертных Reels ключевые сцены располагаются приблизительно в `x=142–814`, начиная с `y=300–350`.
- Полоса субтитров: `x=142`, `w=672`, центр `y=960`; это даёт дополнительный запас под увеличение и обрезку платформы.
- Верх, правую колонку реакций и низ проверять единым Instagram/TikTok/Shorts overlay до финального рендера.
- Лицо может выходить за обычную графическую рамку только как намеренный personal-hero/CTA слой; текст и доказательные объекты — нет.

## Приёмка

- Новый объект или состояние каждые `1–3 с`, но не новая несвязанная сцена.
- В каждой трансформации понятны источник, действие и результат без звука.
- Критические слова и активные узлы находятся в `x≈142–814`, `y≈300–1360`; субтитры используют тот же горизонтальный crop-guard.
- Не более одного крупного фокусного объекта одновременно.
- Эффект без объясняющей функции удаляется.
