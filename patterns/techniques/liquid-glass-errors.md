# Liquid Glass v3 — паттерны и реестр ошибок

Читается до правки `parts/glass.*` любого проекта со `skin: "liquid-glass"`.
Первая часть — как делать. Вторая — что уже ломалось: симптом, причина, починка и проверка,
которая не даёт повторить. Третья — команды, которые эти проверки запускают.

Правило записи: ошибка попадает сюда в том же ходе, когда найдена, вместе с проверкой.
Строка без проверки — не запись, а воспоминание.

## 1. Паттерны

### 1.1 Рабочая колонка (профиль wide-v3)

`reference/platform-guides/instagram-reels/safe-zone-wide-v3-1080x1920.json`

| Зона | Прямоугольник | Что кладём |
|---|---|---|
| critical | 44…840 × 269…1536 | боксы, заголовки, логотипы, окно автора |
| captions | 120…840 × 269…1536 | только полоса субтитров |
| supporting | 0…1080 × 180…1600 | фон, ленты, края стекла |

Правый столбец 840…1080 — рейка кнопок Instagram, туда не попадает ничего, кроме фона.

**Вход бокса даёт `scale 1.06`, поэтому геометрия проверяется не по покою, а по кадру входа.**
Условие для бокса шириной `w` с центром `cx`: `cx ± 1.06·w/2` внутри critical.
Отсюда стандартная колонка широких объектов: `x = 76, w = 732` (центр 442, вход даёт 54…830).
Плюс вход опускает бокс на 28 px: нижняя граница проверяется как `y + h + 28 + 0.03·h`.

### 1.2 Коридор переезда автора

Во время `speakerWindow.moves` окно идёт по прямой из состояния A в состояние B.
Занятой считается **объединение A и B на всё время переезда**, а не текущий прямоугольник.
Любой объект, видимый в эти 0.68 с, лежит вне объединения — либо появляется после приезда.

Практика К1: автор ездит по правой колонке 504…840, поэтому заголовки всех сцен —
в левой колонке шириной 400, а широкие боксы входят после приезда.

### 1.3 Материалы

| Материал | Когда | Преломление |
|---|---|---|
| `clear` | снимок экрана, постер — картинка сама себя контрастит | да |
| `frosted` | текст, цифры, строки — под буквами нужна плотная подложка | да |
| `frosted-lite` | сосед, который держит лимит `maxRefracting` | нет, только blur |
| `smoked` | текст поверх футажа | нет |

Одновременно ≤ 3 преломляющих поверхностей и ≤ 2 blur-only (плюс карточка субтитров).
Три строки списка — это **один** `frosted`-лоток с плоскими строками внутри, а не три бокса.

### 1.4 Движение

`glassEnter / glassExit / sweep / emphasis / connect / mblur` — словарь в `parts/glass.js`.
Числа не переизобретаются: `lg-out 0.16,1,0.3,1`, `lg-in 0.7,0,0.84,0`,
`lg-inOut 0.87,0,0.13,1`, `lg-pop 0.34,1.56,0.64,1`.

- `emphasis` — только для боксов уже ~600 px. Широкий бокс усиливается проходом блика (`sweep`).
- Уход сцены — только по горизонтали. Глубину даёт масштаб фона на `cut: "push"`.
- Motion blur — на материал (`.lg-surface`, `.lg-rim`, ленты). Никогда на лицо, буквы и субтитры.


### 1.6 Раскладка presenter-bottom (решение Александра 11.09.2026)

«Спикер внизу, только чтобы голова не была обрезана, а вверху анимации.»

| Что | Числа |
|---|---|
| Окно автора | квадрат, низ на 1536: `BC 182,1016,520` (центр 442 — как у колонки графики), `BL 44,1016,520`, `BS 440,1136,400` |
| Кроп | `speakerCrop {0,60,1080,1080}`, `object-position 50% 7.1428571%` — верх кадра целиком, голова обрезана быть не может |
| Субтитры | `centerY 920`, полоса 864…976 — **над** окном, зазор ≥ 32 px |
| Графика | 269…830 |

Почему субтитры не остались на 1470: при окне внизу лицо доходит до ~1500, и полоса на 1470
легла бы на подбородок. Правило «субтитры не перекрывают лицо» сильнее правила «субтитры ниже».

Побочная выгода: коридоры переездов автора целиком ниже 1016, поэтому графика сверху вообще
не пересекается с окном — исчезает целый класс ошибок O-4 и коридора 1.2.

### 1.7 Разнообразие приёмов

Замечание Александра 11.09: «паттерны какие-то одинаковые». Правило: **в одном ролике ни один
приём не повторяется дважды, и между роликами набор приёмов разный.** Собранный словарь:

| Приём | Где применён |
|---|---|
| кинетическая строка с лаймовым подчёркиванием | К6 «AI-продукт из Казахстана», К4 «Наоборот» |
| бренд-чип с настоящим логотипом | К6 Higgsfield |
| горизонтальная цепочка со стрелками | К6 «ты → агент → готово» |
| широкий экран плюс колонка слева | К6 «без программирования» |
| чек-лист с прорисовкой галочек | К6 план воркшопа |
| карточка с зачёркиванием | К4 миф |
| переворот сжатием по X (без 3D) | К4 «наоборот» |
| печатающаяся строка ввода (`steps()`) | К4 «пишешь словами» |
| сетка 2×2 с наездом плиток | К4 «что собирают» |
| наклонная записка Caveat | К2 «своё приложение» |
| ряд плоских пилюль | К2 «приложение / сервис / инструмент» |
| строки с крестиками | К2 «раньше упиралось» |
| шкала с бегущей заливкой | К2 «идея → продукт» |
| нумерованные шаги | К2 путь на воркшопе |

Звук тоже не повторяется: палитра синтезируется своим скриптом (`scripts/make-sfx.py`),
а роли раскладываются по файлам в каждом ролике по-своему.

### 1.5 Звук

Событие объявляется в момент создания твина (`cue`), роль резолвится из `glass.audio.palette`.
Стерео — constant-power по x объекта. Дакинг под речь −5 дБ (на −8 акценты пропадают).
Мастер −14 LUFS / −1 dBTP, второй проход `loudnorm` обязан остаться `linear`.

## 2. Реестр ошибок

### O-1. `backdrop-filter: url(#фильтр)` молча не работает
**Симптом.** Преломления нет ни в одном кадре, при этом никаких ошибок.
**Причина.** В `chrome-headless-shell 152` в `backdrop-filter` применяется только `blur`;
ссылка на SVG-фильтр игнорируется. Обычный `filter: url(#f)` работает.
**Проверено.** 10.09.2026, изолированный тест: полосатый фон, три квадрата.
`backdrop-filter` — полосы прямые, `filter` — полосы выгнуты бочкой.
**Починка.** Линза висит не на фоне, а на **копии среды внутри бокса** (`.lg-refract` +
`envClone`), `overflow:hidden` бокса клипует копию до его размера.
**Проверка.** Кадры сборки `tier: full` и `tier: v2` обязаны различаться. Совпали побайтово —
преломления нет.

### O-2. `will-change: transform` на боксе убивает стекло
**Симптом.** То же, что O-1: стекло — плоская плашка.
**Причина.** Элемент с `will-change: transform` (как и с `opacity<1`, `filter`, `mask`,
`isolation`) становится Backdrop Root; потомки перестают видеть фон.
Это была моя собственная «оптимизация».
**Починка.** Снято с `.lg-box`, оставлено только на `#spk`. В CSS стоит комментарий-предупреждение.
**Проверка.** `scripts/check-glass-patterns.sh` — grep по `.lg-box` на `will-change|filter|opacity`.

### O-3. Фейд родителя гасит преломление на время входа
**Симптом.** Стекло «впрыгивает» в конце появления.
**Причина.** `autoAlpha` на `.lg-box`/`.lg-scene` — тот же Backdrop Root, что в O-2.
**Починка.** Правило: `opacity/filter/mask` только на листьях
(`.lg-surface`, `.lg-rim`, `.lg-content`). Видимость сцены переключается `visibility`.

### O-4. Кадр входа выносит бокс за безопасную зону
**Симптом.** `qa.cjs` даёт `safe` на 2–3 кадрах у самого появления объекта, в покое всё чисто.
**Причина.** `glassEnter` даёт `scale 1.06` и `y +28`; проверял геометрию по покою.
**Починка.** Колонка 76…808 вместо 44…840 (см. 1.1), нижние границы с запасом 31 px.
**Проверка.** `qa.cjs` смотрит **каждый** кадр (631 на К1), а не середины сцен.

### O-5. Сдвиг контента вниз даёт ложный `overflow`
**Симптом.** `overflow` на всех боксах ровно в первые 0.1 с входа: `scrollHeight` больше
`clientHeight` на 10 px.
**Причина.** Область прокрутки блока растёт только вправо и вниз. Твин `.lg-content` `y: 10 → 0`
внутри `overflow:hidden` добавлял эти 10 px к `scrollHeight`.
**Починка.** Вход контента идёт вверх: `y: -10 → 0` (и `-8` у детей).
**Проверка.** `qa.cjs`, `kind: 'overflow'` — ноль на всех кадрах.

### O-6. Уход сцены вверх наезжает на окно автора
**Симптом.** Один кадр `overlap: agent-task / presenter-window` на стыке сцен.
**Причина.** Для стыка `push` я уводил боксы на `y -16`, и верхний бокс дотягивался до окна.
**Починка.** Уходы только горизонтальные; глубину даёт масштаб фона.

### O-7. Акцент масштабом на широком боксе ломает зону
**Симптом.** `safe` в момент `emphasis`.
**Причина.** 732 px × 1.06 = 776 px: правый край уходит за 840 при любом центре.
**Починка.** Широкий бокс усиливается `sweep`, а не масштабом. Записано в 1.4.

### O-8. Чужие ручные правки лица в новом проекте
**Симптом.** `face-qa.py`, скопированный из reels-11, содержал зашитые координаты лица
другой записи — на К1 он бы отрапортовал «лицо найдено» там, где его нет.
**Починка.** `manual = {}` в новом проекте, комментарий почему.
**Проверка.** `qa.cjs` сверяет каждый кадр с `source-faces.json`; 84 из 84 семпла на К1 — детект.

### O-9. Кроп окна автора в CSS разошёлся со сторибордом
**Симптом.** `portrait-crop-css-mismatch`: `object-position 28.5714 %` при `speakerCrop.y = 60`.
**Причина.** Проценты были зашиты в скин от прошлой записи, а проверка сверяла их со строкой,
а не с числом.
**Починка.** CSS приведён к записи, `qa.cjs` считает ожидание сам: `crop.y / (1920 − crop.h) · 100`.

### O-10. Приёмка читала старое поле раскладки
**Симптом.** После перехода на `glass.zones` проверка зоны считалась по несуществующему
`glass.safe` и молча пропускала всё.
**Починка.** `qa.cjs` читает `zones.critical` с откатом на `glass.safe` для старых проектов.

### O-11. Глухой мастер
**Симптом.** Ролик звучит «из-под подушки» (случай Vercel: −26.3 LUFS).
**Причина.** `loudnorm` ушёл в динамический режим из-за PLR ≈ 19 у сырой речи.
**Починка.** Пре-компрессия речи (`acompressor 2.5:1`) до сведения; `master-audio.py` падает,
если второй проход не `linear`.
**Проверка.** `finish-master.py`: I −14 ± 0.7 и TP ≤ −0.5 **после** AAC, а не до.

### O-12. Дакинг −8 дБ съел акценты
**Симптом.** Эффектов не слышно: речь занимает 69 % длительности.
**Починка.** −5 дБ, атака 8 / удержание 40 / отпускание 180 мс. Число записано в `mix-audio.py`.

### O-13. `em` в кегле субтитров уменьшил текст
**Причина.** `1.15em` считается от базового кегля родителя, а не от предыдущего значения в px.
**Починка.** Только явные px.

### O-14. Веер субагентов вместо запроса
**Симптом.** 43 агента на ресёрч, лимиты в ноль, ноль роликов.
**Починка.** Два-три агента максимум и только ради независимости суждения; проверка ссылок —
одной командой `curl`. Зафиксировано в `docs/agent-contract/KARPATHY-MONTAGE.md`.

### O-15. Описание к ролику как AI-слоп
**Симптом.** 829 знаков против его настоящих 43 в среднем, длинное тире, описание сервиса
вместо обращения к человеку.
**Починка.** `content-engine/.agents/forbidden-ai-phrases.md`: два предложения, обычный дефис,
формула «Хочешь <результат> - бери <конкретное>».
**Проверка.** `grep -c '—' caption.txt` обязан дать 0.


### O-16. `glassEnter` показывает всех детей контента стаггером
**Симптом.** У карточки-переворота обе стороны видны одновременно: поверх «только для
программистов» проступает «для тех, кто не умеет».
**Причина.** `glassEnter` делает стаггер по `c.children`, если их больше одного. Обратная
сторона, спрятанная через `gsap.set(autoAlpha:0)`, снова открывалась этим стаггером.
**Починка.** Всё, что появляется позже входа бокса, лежит в одной обёртке — у `.lg-content`
ровно один ребёнок. Так же устроены лотки строк и чек-листы.
**Проверка.** Снимок ровно в момент приёма (`snapshot --at`), а не только контактный лист:
на листе с шагом 1.4 с этот кадр можно не поймать.

### O-17. Побайтовая проверка детерминизма ловит шум пересэмплинга
**Симптом.** `non-deterministic-seek` появляется и исчезает от прогона к прогону; сцена
с крупным постером.
**Причина.** Браузер уменьшает картинку чуть иначе при повторной отрисовке: средняя разница
3/255, максимум 51 на кромках букв. Таймлайн при этом одинаковый.
**Починка.** Проверка стала измеряемой: `blend=difference` → счёт пикселей с разницей выше 32.
Порог 0.02 % кадра. Шум пересэмплинга даёт 15 пикселей (0.001 %), пропавший объект дал бы тысячи.
Оба кадра сохраняются в `renders/qa/seek-a.png` и `seek-b.png` — глазами видно, что именно разошлось.
**Правило.** Ослабление проверки допустимо только с числом: сначала измерь распределение
разницы, потом ставь порог. Без замера это просто отключение проверки.

### O-18. Слово короче двух кадров нельзя подчеркнуть
**Симптом.** `missing-underline` на союзе «и» длиной 0.02 с.
**Причина.** Анимация подчёркивания не успевает дойти до 30 % за время меньше кадра.
**Починка.** `scripts/transcribe-words.py` доводит каждое слово до 0.08 с, занимая время
у соседей, но не больше половины их длительности — синхрон не уезжает.

### O-19. Мастер уходит в dynamic из-за пик-фактора
**Симптом.** `master-audio.py` падает: `loudnorm ушёл в dynamic`.
**Причина.** Условие линейного мастера: `true peak − интегральная громкость ≤ 12.6 дБ`.
У К6 было 13.69: подъём до −14 упирался в потолок −1 dBTP.
**Починка.** `mix-audio.py` подбирает ступень компрессии речи замером, а не на глаз:
`(0.891, 4) → (0.80, 4.5) → (0.72, 5) → …` до первой, которая даёт PLR ≤ 12.6.
Выбранная ступень пишется в `renders/qa/audio-mix.json`.

### O-20. Каскад ловит нашивку вместо лица
**Симптом.** На одном семпле из 93 рамка лица уехала на y=921 — на грудь.
**Причина.** Haar-каскад принял нашивку и сложенные ладони за лицо.
**Починка.** Кадр посмотрен глазами (`renders/qa/face-1.75-check.png`), значение взято как
среднее соседних семплов, где автор неподвижен, и записано в `manual` с объяснением.
**Правило.** Ручная правка не берётся глазомером по картинке, если есть соседние измерения.

### O-21. Высота строки считалась формулой вместо факта
**Симптом.** `overflow` на кинетической строке 92 px: `clientHeight 112`, `scrollHeight 119`.
**Причина.** Оценивал line box как `размер × line-height`. Реальный бокс шрифта шире оценки
примерно на 29 %.
**Починка.** Высоты крупного текста подбираются по замеру `qa.cjs`, а не по формуле.
Практика: для Manrope ExtraBold закладывать `1.3 × кегль` на строку.

### Remotion (ролик 21, проба `labs/remotion-route/src/reels/probes`, 19.09.2026)

O-1 подтверждён и на Chrome, который ставит Remotion 4.0.526: `backdrop-filter: url(#линза)` полосы не гнёт.
Рабочее стекло с преломлением — `src/kit/liquid/LiquidPanel.tsx` (копия фона слоя внутри панели + обычный `filter`).

### O-22. feImage с размером в процентах даёт пустую карту
**Симптом.** Линза сдвигает всю панель целиком (и радужит весь текст при хроматике), а не только кромку.
**Причина.** Фильтр лежит в `<svg width=0 height=0>`; `width="100%"` у `feImage` считается от этого нулевого вьюпорта.
**Починка.** Размер карты — числом в пикселях слоя с копией фона (`LensFilter mw/mh`). Проба `LensVariants`.

### O-23. `<g>` внутри `<filter>` молча выключает всю цепочку
**Симптом.** Панель с хроматикой без размытия, без насыщенности и без линзы — как будто фильтра нет.
**Причина.** Примитивы фильтра должны быть прямыми детьми `<filter>`; обёртка `<g>` (в React — от `map`) их прячет,
ссылки `result` рвутся, и Chrome отбрасывает весь `filter`, включая `blur()` и `saturate()`.
**Починка.** В React — `<Fragment key>`, не `<g>`.

### O-24. Сверка кадров только в масштабе 1
**Симптом.** Один и тот же кадр из `renderStill` и из `render --sequence` при `scale 0.5` расходится (PSNR 13–40 дБ),
при `scale 1` совпадает побайтно, включая `backdrop-filter`.
**Правило.** Детерминизм и «отдельный кадр = кадр рендера» проверять при `scale 1`. Уменьшенные кадры — только для глаз.
Проверено цветом кадра: `backdrop-filter` в Remotion берёт фон текущего кадра, не отстаёт (`BackdropLag`).

## 3. Проверки

```bash
bash scripts/check-glass-patterns.sh videos/<project>   # O-2, O-3, O-1 (статически)
node videos/<project>/qa.cjs                            # O-4…O-10 покадрово
python3 scripts/pipe.py validate videos/<project>       # V29 профиль, V30 зоны
python3 scripts/test-safe-profiles.py                   # профиль меняется данными, не константой
python3 videos/<project>/finish-master.py               # O-11 после AAC
```
