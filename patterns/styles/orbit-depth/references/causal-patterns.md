# ORBIT — новые причинные механики

Каталог кандидатов от 14.09.2026. Это не утверждённый новый шаблон и не замена принятому ORBIT. Выбирать механизм под речь, затем показывать реальные кадры; не применять все варианты подряд в каждом выпуске. Пример плана: `videos/reels-17-orbit-7702/MONTAGE-PLAN.md`.

## Что действительно меняется

У каждой сцены: узнаваемый объект → его действие → наблюдаемый результат. Крупность, окраска, переезд портрета и замена фона без нового действия не считаются новыми паттернами. Глубина остаётся ORBIT: передний предмет, причинный путь в середине, дальнее окружение; читаемые интерфейсы/буквы остаются плоскими и неискажёнными.

| Механика | Видимое действие и результат | Камера / звук по действию |
|---|---|---|
| Маршрут со стрелкой-переключателем | Один запрос доходит до закрытого пути; переключатель открывает другую ветку; тот же запрос доходит до ответа. Не изображать независимые перемещения карточек. | Боковое сопровождение запроса; короткий switch в момент изменения пути. |
| Мост между сессиями | Капсула проекта и договорённостей сохраняется после закрытия первой сессии; следующая сессия получает тот же объект. | Перевод фокуса вдоль временного моста; transform на сохранение, тихий UI-акцент на получение. |
| Контекст через компрессор | Стек логов/JSON проходит через фильтр; повторы уменьшаются, ключевая строка остаётся. Сравнение код/логи показывать отдельно, не обещать одинаковый процент для всех данных. | Движение вдоль потока; transform на сжатие. Проценты — подписанная иллюстрация, не сфабрикованный личный benchmark. |
| Сканирование → подбор конфигурации | Полоса сканирования читает узнаваемое дерево проекта, затем выделяет подходящие категории SKILL/MCP. Не показывать установку или изменение файлов, если источник показывает лишь рекомендации. | Краткий наезд на профиль и плавное раскрытие результата; mechanical-zoom / UI-акцент. |
| Обратная связь в навык | Наблюдаемое действие → замечание → предложение изменения конкретного навыка. Одна версия превращается в другую, виден смысл изменения. | Возврат по причинной дуге; switch на фиксацию. Иллюстрацию не выдавать за реальный diff. |
| Возврат к открытой петле | Незакрытый элемент из вступления получает содержательное объяснение в развязке. Напр., пятый улучшает уже подключённые навыки — поэтому показан последним. | Плавный отъезд раскрывает целую систему; короткий resolve из основного пакета, не искусственный alarm. |

## Переходы и вариативность

Сохранять один смысловой якорь через границу: запрос, капсулу контекста или выделенную строку. Следующая сцена принимает этот объект; подписи не morph-искажать. Допустимы последовательное сопровождение, смена направления потока и мягкое разделение глубин. Пролёт камерой не должен заслонять доказательный экран.

Внутри выпуска не повторять подряд один и тот же вход/выход и раскладку. Рандомизировать только совместимые варианты по сохранённому seed: тембр короткого whoosh, фазу дрейфа, направление свободного переезда. Механизм, содержание, громкость и геометрию не выбирать случайно.

Предметы мягко дрейфуют на вложенных transform-плоскостях после входа. Фон движется слабее; контейнер экрана неподвижен относительно читаемых букв. Отдельно проверить амплитуду относительно контейнера на нескольких промежуточных кадрах. Портрет следует свободным коридором и не исчезает ради удобства.

Новые Reels: минимум три смены фона, то есть четыре структурно различных последовательных окружения. Их тайминги записать в `backgroundChanges`; считать переходы, не перекраски. Не делать случайный фон по таймеру поверх важного результата.

## Медиа и экономия

Никакой установки чужих плагинов ради декоративной вставки без отдельного разрешения. Проверять действие в реальном видео, а не доверять названию/README или редкому contact sheet. Screenshot с камерным наездом остаётся screenshot, не видеодемонстрация работы. Старые числа/счётчики не выдавать за сегодняшние.

Кэшировать материалы и звук один раз. Генерировать лишь недостающий смысловой 3D-looking предмет через imagegen: значение → предмет → действие; логотипы только настоящие. Не генерировать каждую сцену/кадр. Для Claude сохранить отобранный ассет и brief; без инструмента он запрашивает ассет, не имитирует генерацию.

До MP4 нужны кадры 0/2/4… и последний кадр, проверки переходов/повторного seek, лица/UI, внутренних размеров после шрифтов, а также отдельное прослушивание SFX под голосом. Только после принятия актуальных кадров — один низконагрузочный экспорт. Эти механики сами по себе не доказывают удержание или вирусность.
