# ONai: схемы и кукольный рассказчик

Общий навык Codex / Claude Code. Корень проекта — Git-репозиторий с `CONTEXT.md` и `scripts/pipe.py`; пути ниже относительно него. Последние решения пользователя важнее старых версий монтажа.

Перед режиссурой прочитай `knowledge/schematic-puppet-layout.md`, перед правкой рига — `knowledge/puppet-approved-and-economy.md`. Штатная сборка/рендер: `docs/agent-contract/MONTAGE-RUNBOOK.md`. Для небольшой правки не загружай сценарные и исследовательские навыки.

## Что меняет решение монтажёра

- Рассказчик не исчезает просто потому, что началась новая сцена. Для каждой сцены задай позицию головы, область объектов и субтитров. Скрытие допустимо на заранее описанном интервале полноценной полноэкранной схемы; укажи момент возврата.
- Объекты главные: занимай свободную высоту и ширину безопасного канваса. Пять узлов не обязаны быть пятью маленькими карточками в один ряд. Для портрета подходят вертикальная сборка и крупный пример, который сворачивается в постоянный узел.
- Голова и оранжевый круг — единый перемещаемый wrapper. Круг: три апельсиновых оттенка, чёрная рамка, медленная слабая смена яркости. Чередуй с cutout, если это соответствует сцене; не перегенерируй лицо. Кукольный рот и чёрную полость сохраняй.
- Для анимации `clip-path` начальная и конечная формы одного типа (например, circle → circle). Несовместимые inset → circle могут кратко вырезать всё лицо. Проверяй вычисленную маску и пиксели промежуточных кадров через рендер-движок.
- Переезд тоже занимает место: сначала вывести голову из полосы субтитров, затем двигать поперёк. Учитывай весь путь и одновременные входы объектов, не только конечные позы.
- Один визуальный объект объясняет конкретную фразу. Для бренда используй настоящий логотип; для понятия — понятную схему/SVG; для сайта — настоящий материал. Не добавляй абстрактные 3D предметы ради «премиальности».
- Линия появляется после обоих узлов. SVG длина через `getTotalLength`; `stroke-dashoffset` и CSS не должны конфликтовать. Все выходы завершаются жёстким скрытием.
- Заголовок и карточки имеют разные области. Замеряй фактическую высоту загруженного шрифта. Субтитры могут переноситься, но текст, курсив и отступы должны оставаться внутри подложки; если строка не вмещается читаемо, раздели группу по речи.
- Проверяй внутренний overflow подписей каждой размеченной `[data-qa]` карточки, а не только её внешнюю рамку и safe-зону. Для текста нужны две проверки: его прямоугольник внутри карточки и собственный горизонтальный `scrollWidth` внутри текстового узла. Не используй `scrollHeight` как самостоятельную ошибку для display-текста: плотный line-height и метрики шрифта дают ложные срабатывания по вертикали. Прямые текстовые дети проверяются автоматически; вложенную критичную подпись помечай `data-qa-fit`. Если длинный термин не помещается, сначала перестрой колонку или увеличь карточку; не лечи это микрошрифтом.

## Реализация и приёмка

Источники: `storyboard.json` и `parts/`; `index.html` генерируется сборщиком. Переиспользуй голос, транскрипт, огибающую и прозрачный видеориг по хешу. Не запускай ASR, генерацию изображений или полный рендер повторно без причины.

До рендера: штатная сборка + проверка геометрии на каждом кадре, включая `contentOverflow` для подписей `[data-qa]`, затем просмотр контакт-листов всех сцен и ключевых промежуточных переходов. `scripts/audit-puppet-composition.cjs` — исполняемый пример для v4 Reels06; требует `composition-qa.json`, `window.__qaMeta`, `.cap-card/.cw` и размеченные `[data-qa]`; вложенные критичные подписи размечай `data-qa-fit`. При переносе обнови селекторы, тайминги, safe-зону и измеренные alpha bounds. Скрипт не является универсальным компьютерным зрением и не оценивает смысл картинки.

После рендера проверь кадры настоящего MP4 с платформенным QA-оверлеем, звук/длительность, наличие головы и движение рта. Только тогда доставляй результат. Мастер не содержит оверлей. Облачную синхронизацию подтверждай отдельно от локального копирования; не выключай машину и не публикуй ролик без соответствующей команды.

Запиши реальные измерения и оставшиеся ограничения в `REVISION.md`. PASS программы — один слой проверки, а не одобрение пользователем. Разделяй качество экспорта, время CPU и токены агента; это разные метрики.
