# ONai на Remotion: единый холст, глубина, дизайн-система

Решение Александра 18.09.2026: «Мы оставляем Remotion. Этот стек теперь для Codex и для Claude: Remotion, Storybook для просмотра — витрина, где каждый блок ролика смотрят отдельно, HeroUI». Маршрут, от которого стек взят: `reference/breakdowns/pronin-route-2026-09-18.md`. Рабочий образец и шаблон нового проекта: `labs/remotion-route/` (README с командами).

Общие правила кадра остаются в силе: спикер снизу в карточке Screen Studio с тремя размерами, субтитры 40 px светлые, холст с камерой на схемах и смена сцен в остальном ролике, звук из `reference/audio/onai-apple-pack`, 2K 1440×2560, снимки каждые 2 с и стоп до одобрения — `knowledge/agent-entrypoints.md`, `knowledge/montage-final-contract.md`.

## Уровень рассуждения (решение Александра 18.09.2026)

Монтаж — всегда **xhigh**: Claude — Opus 5 с `--effort xhigh` (в Claude Code это и уровень по умолчанию), Codex — `gpt-5.6-sol` с `model_reasoning_effort = "xhigh"`. Ниже не опускать ни на режиссуре, ни на сборке, ни на правках. `max`, `ultra` и Fable 5.1 для рядового ролика не нужны. Сам агент уровень посреди сессии не меняет — он задаётся при запуске (`scripts/session.sh` ставит xhigh всем этапам монтажа). Один ролик — одна свежая сессия.

## Стек

- **Remotion** — сцены пишутся React-компонентами, анимация только через `useCurrentFrame`, `interpolate`, `spring`. CSS-анимации и Tailwind-анимации в рендере не работают. Официальные навыки агента: `npx skills add remotion-dev/skills --all -a claude-code -y` (для Codex — `-a codex`), правила `remotion-markup`.
- **Storybook** — каждый блок (пилюля, панель, текст с глубиной, карточка спикера) смотрится отдельно в своих состояниях; весь ролик — через `@remotion/player` с перемоткой. Блок сначала принимается в витрине, потом идёт в ролик.
- **HeroUI v3** — основа дизайн-системы: `Chip`, `Card` и остальные компоненты. Поверх — слой ONai `src/ds/`: токены глубины, шкала кеглей для видео, проверка контейнеров. Классы HeroUI с `!` (important) не использовать для полей: они перебивают наши отступы — так 18.09 получились кривые пилюли.

## 4K и качество объектов (решение Александра 18.09.2026)

- **Вывод — 2K 1440×2560, 48 Мбит/с** (Александр, вечер 18.09.2026: «4K очень долго»); `Config.setScale(1)`, 4K только по отдельной просьбе. Ниже — как делать 4K, если попросят.
- 4K 2160×3840. Композиция остаётся 1440×2560 (все токены раскладки в её пикселях), `remotion.config.ts` ставит `Config.setScale(1.5)`: браузер пересчитывает текст, вектор и 3D в 4K, ничего не растягивается. Кадры владельцу: `SCALE=1.5 node scripts/stills.mjs <Composition> <кадры>`; для своей проверки хватает 0,25.
- Видеокарта в WSL браузеру рендера недоступна: WebGL идёт через SwiftShader или llvmpipe, то есть на процессоре. Замер: 90 кадров — 31 с в 2K и 53 с в 4K (×1,7), минута ролика в 4K ≈ 18 мин при concurrency 2. Кодирование NVENC (`h264_nvenc`) работает, но узкое место не в нём.
- Объекты — настоящее 3D через `@remotion/three` (three.js): физический материал, студийное окружение `RoomEnvironment`, свет сверху слева, анимация только от `useCurrentFrame()`. Общая основа — `src/kit/three.tsx`: `ObjectStage` (прозрачный холст, свет, студийное окружение), `ring` (контур с отверстием и фаской), `slab` (плашка). Образцы — `Porthole.tsx` и `PhoneMock` в `Phone.tsx`: 3D-корпус поверх HTML-окна, поэтому переходы и содержимое остаются в DOM. Владелец принял 3D-раму иллюминатора 18.09.2026 («вот сейчас классно»). Ширина кольца должна быть больше двух фасок, иначе контур с отверстием выворачивается и закрывает окно сплошной заливкой. Плоская имитация объёма на CSS-градиентах отклонена («иллюминатор плохого качества»).
- Битрейт финала в 4K — цель не ниже 80 Мбит/с, фактический замеряется по файлу.

## Палитра и объекты (правка 18.09.2026)

- Цвета — **оранжевый, мятный (бирюзовый), чёрный, белый**. Акцент — мятный `#3DEDC3` (текст на нём `#05231D`), второй акцент — оранжевый `#FF7A2F`. Синего и фиолетового в фонах и акцентах нет — владелец их отклонил. Лайм `#B6FF00` в новом стеке заменён мятным.
- Зоны холста: тёплая (оранжевый свет на чёрном), мятная, чёрная с мятой и оранжевым.
- 3D-объектов мало: не больше одного на зону и только по смыслу речи. Россыпь шестерёнок и ракет «для красоты» — нет.
- **3dicons запрещены (18.09.2026):** владелец назвал их «не то качество» и «не та палитра». Предмет в кадре — вектором в дизайн-системе (`Sticker`, `Porthole`, `Toggle`, `PhoneMock` из `src/kit`), настоящий логотип или запись экрана; 3D-объект — только сгенерированный Codex под палитру и проверенный глазами. Пример замены: в иллюминаторе вместо иконки чата — наклейка «в месяц / $7», как календарь у автора.

## Стекло (правка 18.09.2026)

- Подложки — стекло: 50–60% прозрачности, размытие и насыщение того, что за ними (`glass.clear` — заливка 42%, `glass.frosted` — 55%). Сплошная подложка (`solid`) — только в ключевой момент: боль, победа, призыв. Лаймовые акценты всегда сплошные.
- Жидкое стекло: светящийся обод (свет слева сверху, отблеск справа снизу), блик сверху, внутренняя тень снизу — `GlassLayers` в `src/ds/Glass.tsx`.
- Стекло размывает только то, что лежит с ним в одном слое. У предков стеклянного блока не должно быть `filter`, `opacity` меньше 1, `mask`, `clip-path`, `mix-blend-mode` — иначе фон за стеклом пропадёт (правило Backdrop Root). Поэтому фон, объекты и блоки лежат в одном слое камеры без масок и размытий.

## Фоны под стекло

- Каждая зона холста — своя палитра: базовое пятно, 2–3 световые сферы, диагональные полосы света, сетка, лёгкий шум. Стеклу нужно, что размывать; ровный тёмный фон делает стекло невидимым.
- 3D-объекты по теме зоны лежат на дальнем плане (скорость 0,7 от камеры), видны, только когда камера у своей зоны, и чуть размыты. Объекты по теме генерирует Codex под палитру; 3dicons не использовать.
- Слою со сдвигом давать размер (ширину и высоту холста): контейнер нулевого размера с `translate` рендер отбрасывает вместе с содержимым.

## Карта монтажа — своя архитектура под каждый ролик (Александр, 18.09.2026)

Первый ролик на этом стеке (`videos/reels-19-direct-assistant`) владелец назвал «охуительный монтаж… разъеб» и сразу поставил условие: **«нельзя каждый раз это юзать… под каждый монтаж разрабатывать свою архитектуру, эту карту делать»**. Повтор одного набора приедается. Поэтому переносится метод, а не сцены.

**Каждый раз заново придумываются:**
- **героический объект хука** — в ролике 19 это 3D-иллюминатор с «$7». В следующем ролике он другой, по смыслу первой фразы;
- **форма схемы на холсте** — в 19 это «узел в центре, к нему летят ключи». Бывает цепочка, развилка с выбором, таймлайн, воронка, «до/после» — выбирается по тому, как устроена мысль в речи;
- **вставки** — какие настоящие записи, макеты и 3D-предметы несут смысл именно этого текста; хотя бы одна новая вставка или предмет на ролик уходит в библиотеку `src/kit`;
- **набор и порядок переходов** — из библиотеки, но каждый стык обоснован фразой: влёт в окно — «вот оно», рывок — контраст, вспышка цвета — раскрытие результата, сжатие в узел — вход в схему, уход в тёмное — призыв;
- **зоны цвета** под смысловые блоки этого текста.

Иллюминатор, наклейки «$7 / $25», тогл «вручную → автомат» и порядок сцен ролика 19 **не копировать** в следующий ролик. Готовый блок из `src/kit` можно взять, если он по смыслу ложится, но не весь набор и не в той же роли.

**Порядок работы:**
1. Пословная расшифровка → фразы с таймингом.
2. **Карта монтажа** в DIRECTION.md проекта, до кода: таблица «время → фон → что на экране → стык → карточка спикера». Столбец «фраза → объект → действие → зачем» — образец в `videos/reels-19-direct-assistant/PATTERNS.md`. Настоящие записи ставятся на точную фразу, где их смысл, например запись бота — на «по кодовому слову присылает материалы».
3. Записи экрана раскрываются почти на всю ширину кадра и идут целиком, с кликами (просьба владельца). Приватное (почта, карта, ключ) размывается в самом файле по кадрам — `videos/reels-19-direct-assistant/tools/blur_private.py`.
4. Сборка → `qa-fit` → проверки ниже → только потом рендер.

**Проверки, которые поймали реальные дефекты в ролике 19:**
- первый кадр не пустой;
- число не показывает «$0» до начала счёта;
- после стыка нет пустого фона;
- летящий объект не пересекает другие (8 кадров на пролёт, маршрут — кривой в обход);
- объект не появляется на полосе субтитров, пока камера не доехала;
- хвосты прошлых зон гаснут полностью;
- размер шрифта в мире ≥ минимум / масштаб камеры;
- 3D-кольцо не выворачивается.

Контроль: кадры каждую секунду, по 8 кадров на каждый стык, середины всех переездов камеры, лист из готового MP4.

## Стиль «техно-постер» (утверждён Александром 19.09.2026, ролик 20)

## Два режима: сцены и холст (решение Александра 18.09.2026, вечер)

Холст с камерой владелец оставил, но **не на весь ролик**: только там, где показываем схему работы (кто с кем связан, куда идут данные, по шагам). Всё остальное — **режим сцен**: фон меняется каждые 3–7 с по смысловым блокам речи, между сценами — переходы из референса Пронина. Разбор по кадрам: `reference/breakdowns/pronin-canvas-2026-09-18.md`, раздел «Сцены».

Библиотека режима сцен — `labs/remotion-route/src/kit`, демо — композиция `SceneKit`, витрина — Storybook, раздел «Сцены»:

| Блок | Что делает | Откуда в референсе |
|---|---|---|
| `Backdrop` | фоны `black`, `graphite`, `white`, `mint`, `ember`, `sky` (закатное небо вместо голубого, облака вектором) + зерно и виньетка; `ink[kind]` — цвет текста с контрастом ≥ 4.5:1 | чёрный → небо → чёрный → фиолетовое свечение → чёрный холст → белый → чёрный |
| `portal(окно)` | камера влетает в окно предмета, нутро становится следующей сценой; окно в координатах кадра, для иллюминатора — `portholeWindow()` | иллюминатор, 2,0–2,3 с |
| `blurThrough({color})` | сцена плывёт вверх и мутнеет, кадр заливается цветом следующего фона | небо → чёрный 5,8–6,1; сетка → белая вспышка 29,0–29,3 |
| `bloom({color})` | свечение цвета следующей сцены растёт поверх текущей | балаклава → фиолетовое свечение 9,9–10,3 |
| `whip({dir})` | обе сцены едут одной лентой, размытие только по оси движения (SVG-фильтр) | ключ улетает, 12,5–12,8 |
| `shrinkTo({x, y})` | сцена сжимается в точку, где появляется первый узел схемы — вход в режим холста | ключ → узел карты, 12,5–13,5 |
| `lift()` | сцена уезжает вверх и гаснет в тёмное | тогл → база знаний, 39,2–39,5 |
| `Porthole` | иллюминатор — 3D-рама на three.js поверх HTML-окна, в окне фон следующей сцены | 0,3–2,0 с |
| `Toggle` + `Cursor` | тогл с подписями «было / стало», курсор дугой, щелчок, ручка едет, подписи меняют вес | «вручную → автомат», 36,6–38,4 |
| `PhoneMock`, `DmHeader`, `ChatThread` | 3D-корпус телефона (титановый ободок, глянцевая кромка, кнопки) поверх HTML-экрана; лента директа с автопрокруткой, «печатает…», голосовое | вставки с профилем и каналом, чат 29,5–36 |
| `Toast` | уведомление сверху со значком сервиса | — |
| `BlurIn`, `RiseIn`, `Pop` | слова из размытия, подъём снизу на пружине, выпрыгивание с покачиванием | все сцены |

- Тогл у автора — Switch из HeroUI. В Remotion CSS-переходы не рендерятся, поэтому геометрия как у Switch, а положение ручки считается от кадра.
- Сцены собираются в `TransitionSeries` из `@remotion/transitions`; переход съедает свою длину из стыка. Карточка спикера и звук лежат поверх серии.
- Переход с фильтром или маской выключает размытие стекла во входящей сцене, пока идёт стык. Поэтому сцена начинается с заголовка, стеклянные панели выходят после стыка.
- На стыке не должно быть пустого фона: первый объект следующей сцены появляется до конца перехода (у `shrinkTo` — в той самой точке).

## Холст (режим схемы)

- Фон — часть мира, а не подложка экрана. Камера едет по одному холсту, и зоны цвета плавно сменяют друг друга. Слои фона, которые перелистываются на экране, запрещены.
- Внутри схемы смена фона — переезд камеры в другую зону цвета того же холста, а не подмена экранного слоя.
- Параллакс: дальний слой едет со скоростью 0,55 от камеры, сетка и содержимое — 1, ближняя пыль — 1,25. Наклон холста до 7° и размытие до 5 px только во время переезда, в покое кадр ровный, текст не искажён.
- Маршрут между блоками рисуется пунктиром по ходу движения, предыдущий блок остаётся видимым якорем.

## Глубина везде

- Текст не лежит плоско: крупные цифры и заголовки — `DepthText` (выдавленная подложка + градиент), обычный текст — тень `textDepth`.
- Контейнеры — фаска (свет сверху, тень снизу) и уровень высоты 1–3 из `elevation`.
- Карточка спикера — внутренний контур и тень третьего уровня.

## Проверка перед показом кадров

1. `node scripts/qa-fit.mjs <Composition>` — каждые 0,5 с рендерит кадр в режиме qa и ловит нарушения из браузера: содержимое не помещается или поле меньше половины кегля. Нужен `FIT PASS`.
2. `node scripts/qa-fit.mjs FitTest` обязан дать `FIT FAIL` на двух контейнерах — это доказательство, что проверка жива.
3. Затем снимки каждые 2 с, лист, стоп до одобрения.
4. После рендера звук довести до −14 LUFS / ≤ −1 dBTP двухпроходным loudnorm: Remotion громкость не выравнивает (пример 18.09 вышел −22,8 LUFS).

## Грабли, которые уже стоили времени

- `sideEffects` в package.json: при `["*.css"]` сборщик молча выкидывает модуль шрифтов, текст уходит в засечки. Держать `"**/fonts.ts"` в списке.
- Storybook рядом с Remotion ставится с `--legacy-peer-deps`, а HeroUI требует отдельно `@react-aria/utils`, `@react-aria/ssr`, `react-aria`, `react-aria-components`, `@internationalized/date`.
- Консоль браузера в `remotion still` до терминала не доходит; поэтому проверка идёт через API рендера с `onBrowserLog`.

## Liquid Glass с настоящим преломлением (ролик 21, 19.09.2026)

Библиотека `labs/remotion-route/src/kit/liquid` — приёмы и грабли подробно в `videos/reels-21-montage-agent/PATTERNS.md`.
- Стекло с преломлением — `LiquidPanel` внутри `GlassEnv`: панель рисует копию фона слоя шире себя и вешает обычный `filter` (размытие → линза по карте кромки → насыщенность). `backdrop-filter: url()` в Chrome Remotion не работает (O-1); копия живёт и во время переходов с фильтрами. Размер карты `feImage` — в пикселях (O-22), примитивы фильтра без `<g>` (O-23), сверка кадров только в масштабе 1 (O-24).
- Капсула-выделение по реальной ширине слов — `CapsuleLine`; субтитры-капсула под строкой — `src/reels/montage/Captions.tsx`.
  **Капсулы шире текста с запасом** (Александр, 20.09.2026: «текст местами чуть вылезает»): поля ≥ 0,4 кегля по бокам и ≥ 0,12 сверху/снизу — advance-ширина слова не учитывает выносы глифов; у субтитров-капсулы ≥ 48 px по бокам при 53,3 px.
- Свет: прожекторы с пылью, луна с кратерами и лунным лучом, рифлёное стекло, небо с подъёмом над облаками, платиновая студия — `stage.tsx`. Сгенерированные предметы — `Object25D`.
- Пролёт сквозь букву — `Glyph.tsx` + `scripts/glyph-paths.mjs` (fontkit, вариативный вес).
- Шрифты для замеров — только через `useFontsReady` из `kit/liquid/useAssetReady.ts` (ждёт, пока шрифт реально появится; иначе строки слипаются в отдельных кадрах).
- Параллельная работа: у ролика своя точка входа (`src/index-<ролик>.ts`), общий `Root.tsx` не трогать; тяжёлые рендеры согласовывать с соседней сессией сообщением «рендерю … / свободно».

## Сценарный канвас (ролик 22, 20.09.2026)

Монтаж как один канвас, а не набор сцен: листы смысловых блоков лежат на общем столе, камера едет от листа к листу по пунктирной
связке, которую тянет курсор агента, на месте виден угол прошлого листа. Реализация — `src/reels/course/live/`:
`canvas.tsx` (камера ключами, курсор, выделение, клавиши), `desk.tsx` (стол, листы с тетрадной разлиновкой, связки),
`Hourglass.tsx` (3D-предмет), `scenes1–3.tsx` (содержимое листов), `ReelLive.tsx` (сборка).

Правила, которые дал Александр по ходу этого ролика:
- фон — графит с шумом и **тетрадной сеткой** (клетка, линейка, миллиметровка, точки); оранжевый и мята — только акценты;
- **чередовать тёмные и светлые листы** (референс Пронина: чёрное → небо → чёрное → белый чат);
- комбинировать канвас с другими приёмами: влёт внутрь экрана (портрет-экран телефона подходит по пропорции), подъём предмета
  снизу, отъезд на общий план, резкий рывок;
- предметы брать из `public/objects` (стеклянные рендеры) и добавлять недостающий через `scripts/gen-object.mjs`;
- свои звуки под каждый ролик — новые нарезки из пака;
- уникальная концепция под каждый Reels: набор прошлого ролика не переносить.
