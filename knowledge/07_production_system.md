# Production system: экспертные Reels и подкаст-нарезки
> В публичной версии репозитория папки `content-engine/` нет: пункты о ней пропускай, голос и доказательность бери из `knowledge/06_copywriting.md`.


Версия: `2026-08-31`. Это рабочая операционная система ONai: как пройти от длинного
исходника или идеи до опубликованного ролика, сохранить качество, не перегрузить компьютер и
не скатиться в «AI-слоп».

Точные платформенные координаты субтитров и исключения вынесены в
[`reference/platform-guides/instagram-reels/adaptive-caption-placement-1080x1920.md`](../reference/platform-guides/instagram-reels/adaptive-caption-placement-1080x1920.md).

## 1. Почему архитектура устроена именно так

Система появилась из нескольких проверенных итераций, а не из набора случайных «виральных»
приёмов.

1. CapCut оказался закрыт для надёжной генерации проекта, Shotcut не сохранил нужные шрифты,
   логотипы и анимации, Remotion Studio не стал визуальным редактором, а DaVinci не входит в
   рабочий стек пользователя.
2. Прозрачные Remotion-оверлеи дали библиотеку полезных компонентов, но не могли управлять
   базовым видео без дополнительного прохода. Они остались запасным путём.
3. HyperFrames объединил исходное видео, отдельную речь, SFX, HTML/CSS и детерминированный
   GSAP-таймлайн в одной композиции. Поэтому он стал основным renderer/runtime.
4. Первые версии с текстовыми плашками поверх лица были читаемыми, но не объясняли мысль.
   Версии, где карточки постоянно заменяли друг друга, не формировали структуру. Рабочим стал
   монтаж, где визуальная система сохраняет пространственную логику, а содержимое меняется по
   смыслу.
5. Пользовательское ревью удалило зумы ради зумов, меняющиеся заголовки, псевдо-интерфейсные
   подписи и декоративные объекты без функции. Финальный принцип: каждый объект либо
   объясняет связь, либо доказывает факт, либо ориентирует взгляд — иначе его нет в кадре.

Отсюда четыре независимых слоя:

```text
Смысл        research → angle → transcript/script → scoring
Режиссура    storyboard → semantic scenes → assets → sound map
Производство HyperFrames/GSAP → check → low-I/O render → technical QA
Обучение     publish → analytics → review → durable knowledge/winners
```

Разделение обязательно. Нельзя пытаться одновременно придумывать тезис, переписывать речь,
рисовать экран и чинить рендер: тогда ошибка смысла маскируется дорогой анимацией.

## 2. Что должно быть на входе

### Общие входы

- формат: `podcast cut` или `expert Reel`;
- площадка, длительность и один целевой результат;
- актуальная бренд-память из `knowledge/personal-brand-content-system.md`;
- одна основная CTA-точка и подтверждённая ссылка;
- права на исходник, логотипы, экранные записи, музыку и SFX;
- технический контракт: `1080×1920`, `30 fps`, квадратный пиксель, нулевая rotation;
- референс нужен как язык решений, а не как инструкция копировать чужие декоративные детали.

### Для подкаста

- мастер-видео может быть 4K и весить много гигабайт;
- извлечённая аудиодорожка или лёгкий proxy для анализа;
- пословный транскрипт с таймингами и, если возможно, разметкой спикеров;
- полный связный транскрипт для проверки контекста;
- разрешённый диапазон длительности и список нежелательных тем.

Большой мастер не нужно многократно декодировать. Анализ идёт по аудио/proxy и транскрипту;
оригинал читается только после выбора конкретного фрагмента.

### Для экспертного Reel

- утверждённая spoken-речь без монтажных ремарок;
- исходная говорящая голова;
- список упомянутых продуктов, экранов, фактов и связей;
- статус каждого экранного доказательства: реальное, ещё не опубликовано, требует записи.

Если статья или продукт ещё не опубликованы, нельзя рисовать фальшивую страницу. Используется
реальный доступный экран и честная пометка в project brief.

## 3. Research и доказательность

Research отвечает не за «больше фактов», а за право показать и произнести конкретное утверждение.

1. Прочитать product/audience context и proof policy в `content-engine/.agents/`.
2. Сформулировать одну главную мысль ролика и одно действие зрителя.
3. Проверить изменяемые факты по первичным источникам: официальная документация продукта,
   публичный интерфейс, собственный репозиторий, лог или измерение.
4. Для спорного числа или сравнения записать: точную формулировку, тип утверждения, источник,
   область применимости, коммерческий интерес источника и способ проверки.
5. Разделить `verified`, `supported`, `plausible-test`, `unsupported`, `contradicted`.
   В канонический сценарий как факт проходят только первые два статуса.
6. Для чужих курсов и советов блогеров включить skeptic gate: что реально доказано, что
   является продажной интерпретацией и что ONai может измерить своим экспериментом.

Research-артефакты остаются в репозитории. В пользовательский `.txt` попадает только речь.

## 4. Поиск и scoring подкаст-фрагментов

Рабочий pipeline описан в `workflows/podcast-clip-mining.js`.

1. Разделить длинный транскрипт на части с небольшим перекрытием.
2. Найти фрагменты по границам законченной мысли, а не по круглым таймкодам.
3. Отбросить приветствия, представления, переходы и общие рассуждения без конкретики.
4. Проверить спикера и местоимения по полному контексту. Высокий балл не отменяет ручную
   проверку: пересказ чужой цитаты может выглядеть как личное утверждение спикера.
5. Оценить кандидата по пяти шкалам по `0–20`:

| Критерий | Контрольный вопрос |
|---|---|
| Hook | Работает ли первая фраза в первые три секунды? |
| Самодостаточность | Всё понятно без предыдущих пяти минут? |
| Конкретность | Есть цифра, имя, действие, механизм или пример? |
| Эмоция/спор | Возникает узнавание, тревога, интерес или аргументированный спор? |
| Законченность | Мысль закрыта выводом и не обрывается? |

Порог: `70–100` — в работу, `50–69` — запас, ниже `50` — не монтировать. Обычная длина
кандидата — `25–70 секунд`, если brief не задаёт другой формат. После human gate точные
таймкоды передаются в `scripts/cut.py` или в проектный import script.

## 5. Сценарий и angle

Для экспертного Reel порядок такой:

```text
research brief → один angle → spoken draft → Copychief → cleanup → запись
```

Правила:

- первая фраза начинает с напряжения, решения или конкретной ошибки, без приветствия;
- один Reel доказывает одну главную мысль;
- первые `3–4 секунды` дают trigger title/hook;
- каждые `6–10 секунд` появляется мини-payoff: пример, ограничение, переход или новый факт;
- сложное объясняется обычным примером и реальной связью компонентов;
- CTA один, по пользе, до `5 секунд`;
- финальная речь не содержит таймкодов, кадров, B-roll, музыки и команд монтажёру;
- запрещены шаблонные AI-формулы из `content-engine/.agents/forbidden-ai-phrases.md`;
- сценарий читается вслух до записи: дыхание и разговорный ритм важнее симметрии абзацев.

Монтажный план создаётся только после утверждения речи. Он не возвращается в spoken script.

## 6. Storyboard как контракт

Каждый проект хранит человекочитаемый `STORYBOARD.md` и машиночитаемый `storyboard.json`.
Для каждой сцены нужны:

- точный `startSec/endSec`;
- дословный фрагмент речи или привязка к word timings;
- `intent`: что зритель должен понять после сцены;
- режим: full-screen speaker, split speaker/canvas или full-screen explanation;
- фактический asset/source;
- смысловая механика анимации;
- caption preset;
- sound event, если он помогает переходу;
- риск коллизии с лицом, логотипом, CTA или Reels UI.

Визуальное обновление примерно раз в `3–4 секунды` — рабочая гипотеза удержания, не повод
дёргать кадр по таймеру. Если мысль продолжается, меняется активный узел, состояние или
доказательство внутри той же системы. На важном выводе допустима короткая визуальная пауза.

## 7. Семантический монтаж

Анимация должна показывать глагол или отношение, а не повторять существительное из речи.

| Смысл | Что показывать |
|---|---|
| Выбор | ветвление с критериями и отсеянной альтернативой |
| Последовательность | путь, узлы и активный token |
| Причина → следствие | соединение, передача состояния, результат |
| Данные | запись пользователя/заказа в реальную модель БД |
| Контейнеризация | компоненты входят в контейнер, затем тот же контейнер проходит на сервер |
| Ограничение | конкретная красная ошибка и исправляющий guardrail |
| Доказательство | реальный интерфейс, лог, репозиторий или документ |
| Архитектура | одна читаемая схема связей, а не облако логотипов |

Успешный ролик про стек использовал именно такие соответствия: React/TypeScript — реальные
поверхности интерфейса; Python/FastAPI и Express — ветки выбора; PostgreSQL — записи данных;
LangGraph — исполняемый маршрут; OpenRouter — реальный каталог; Docker — одинаковое окружение
ноутбука и сервера.

Технические правила HyperFrames:

- один детерминированный GSAP timeline; никакого `Math.random()` в кадре;
- продолжительность композиции берётся из storyboard, не вычисляется «на глаз»;
- HyperFrames сам управляет `.clip`: opacity/visibility анимируются на внутренней обёртке;
- слова в кинетическом заголовке оборачиваются целиком, чтобы не рваться между строками;
- canvas full-bleed, но критический контент держится в safe zones;
- основной код — `index.template`, `index.html` генерируется проектным builder script.

## 8. Assets: только реальные и релевантные

Приоритет материалов:

1. собственный экран, репозиторий, статья, лог или демонстрация;
2. официальный логотип/brand asset названной технологии;
3. кодовая схема, построенная из реальных сущностей речи;
4. лицензированный stock только когда он буквально иллюстрирует сказанное;
5. генеративная иллюстрация — исключение, а не заполнитель пустоты.

Для логотипов проект использует `ASSET_SOURCES.md` и `scripts/fetch_brand_assets.py`. Скрипт
скачивает официальные SVG/ZIP, проверяет SHA-256 и отбрасывает активное содержимое SVG.
Пропорции и clear space брендов не искажаются. Логотип не используется как одобрение продукта.

Для реальных интерфейсов:

- убрать ключи, email, личные данные, billing и лишние вкладки;
- сохранить домен/контекст, чтобы доказательство не выглядело выдуманным;
- записывать только нужное действие; направленный zoom допустим, когда он ведёт к реальному
  контролу интерфейса, а не просто «делает динамику»;
- публичный capture хранить отдельно от авторизованного master; в Git не класть секреты.

## 9. Caption system

Общее:

- canvas `1080×1920`;
- compact caption wrapper `x=120`, `w=720`, `h=112`; speaker portrait card отдельно
  использует `x=120`, `w=744`;
- утверждённая чёрная подложка `30% opacity` (`rgba(4,4,4,.30)`); затемнять её можно только при провале читаемости в QA;
- основной шрифт стабилен; курсив выделяет только `1–2` смысловых слова либо живёт отдельным
  handwritten callout на canvas;
- курсив не уходит за `x=120–864` и не превращает всю строку в декоративную;
- основной caption не прыгает пословно и не меняет гарнитуру без смысловой причины.

### Podcast nominal preset — 50%

- центр карточки: `Y=960`, ровно `50%` высоты;
- верх: `Y=904`, низ: `Y=1016`;
- карточка пересекает шов между верхним объяснением и нижним спикером;
- это nominal anchor; конкретный speaker crop всё равно проходит head-clearance.

### Expert Reel nominal preset — 65%

- центр карточки: `Y=1248`, ровно `65%` высоты;
- это на `15%` кадра, или на `288 px`, ниже центра;
- верх: `Y=1192`, низ: `Y=1304`;
- цель — не закрывать центральную говорящую голову и перенести чтение в нижнюю часть кадра;
- full-graphics может резервировать эту полосу без лица; talking-head использует её только после
  face-clearance.

### Split и full-graphics lanes

- Экспертный split использует compact fallback `x=120–840`, `y=816–928`,
  `centerY=872`; hard gap `32 px` до panel `Y=960`. Podcast `centerY=960` — отдельный preset.
- Full-graphics main-caption занимает отдельную полосу `x=120–840`, `y=480–592`.
  Активные узлы и подписи схемы резервируют эту полосу до анимации.
- Отдельный курсивный semantic callout живёт только в safe band `x=200–820`,
  `y=1030–1160`. Он является отдельным canvas-layer и не заменяет основной subtitle font.
- Не включать semantic callout одновременно со split-caption, если они конкурируют за
  внимание; переносить callout в full-graphics или caption-free beat.
- Переход между утверждёнными main-caption presets анимируется вместе со сменой layout.

`Y=1248` — правило органического expert Reel. Карточка заканчивается ниже консервативной
нижней зоны Meta для рекламы, поэтому перед использованием того же master как paid ad caption
поднимается и проверяется отдельно.

### Face/head clearance overrides static anchors

- Sparse analysis идёт по source video до render: один кадр в секунду по умолчанию.
- Expert portrait caption начинается минимум на `32 px` ниже transformed chin (`48 px`
  preferred); head/face/eye intersection = fail.
- При bottom UI `Y=1360`, reserve `24 px` и `h=112` последний legal top — `Y=1224`.
- Нет legal slot — `LAYOUT_SWITCH`, не перенос на рот или бороду.
- Expert split использует reviewed compact `Y=872`; podcast сохраняет `Y=960`.

Фактический `IMG_7333`: 54/54 detections; после object-fit portrait reframe chin
`Y=851…1110`, standard expert `PASS 54/54`, compact split `Y=872` `PASS 54/54`. Первый short-title
crop поймал конфликт на `03.0–04.0s`; после сокращения speaker-card до `y=540–1160` повторный
title gate прошёл `7/7`. Артефакты находятся в
`videos/vibecoding-stack-2026-img7333/analysis/face-*`.

## 10. Anti-AI-slop gate

Каждый смысловой foreground-объект проходит шесть вопросов. Базовый платиновый фон, сетка и
свет оцениваются отдельно как бренд-система. Один ответ «нет» означает: исправить или удалить.

1. Он объясняет конкретную связь, состояние, доказательство или следующий шаг?
2. Он связан с произнесённой фразой именно сейчас, а не просто «про AI вообще»?
3. Данные, интерфейс, логотип и подпись настоящие и проверяемые?
4. Без него зрителю станет труднее понять мысль?
5. Он читается после Reels crop и не конкурирует с caption/лицом?
6. Его движение имеет начало, цель и завершение, а не бесконечно шевелится?

Hard fail независимо от красоты:

- псевдо-HUD, fake timeline, `CASE 01`, декоративный progress bar и технические подписи,
  которые не несут данных;
- generic AI brain, нейросетевые линии, фиолетовый neon, бессмысленные circuit patterns;
- выдуманные экраны, цифры, кейсы, статусы, логи и «метрики»;
- случайное облако логотипов без архитектурной связи;
- unrelated gameplay, мем-лента и Subway-Surfers-подобный attention filler;
- верхний заголовок, который просто дублирует читаемые субтитры;
- анимация каждой буквы/слова без смыслового акцента;
- декоративный объект, добавленный только потому, что в кадре осталось пустое место.

Human gate делается по storyboard до кода и повторяется на contact sheet до финального рендера.

## 11. Звук

Речь — главный трек. Проектный import нормализует её через high-pass, мягкую компрессию и
`loudnorm I=-16, TP=-1.5, LRA=7`, затем сохраняет `48 kHz AAC 192 kbps`.

SFX работают как пунктуация:

- impact — только hook или крупный verdict;
- короткий transition — смена режима layout;
- click/commit — реальное появление записи или подтверждённого состояния;
- error — одна конкретная ошибка;
- chime — завершённый результат/CTA.

Используется небольшая повторяемая палитра звуков на низкой громкости, а не новый эффект на
каждое движение. Не ставить whoosh на каждое слово. Перед повторным использованием внешнего SFX
его источник и лицензия фиксируются в локальном manifest; звук без подтверждаемого provenance
заменяется на source-tracked asset.

## 12. Рендер без потери качества и зависания компьютера

Основной профиль проекта: `npm run render:low-io`.

- HyperFrames `0.8.20`, `1080×1920`, `30 fps`;
- `--workers 1` сохраняет streaming encode и не размножает браузеры;
- frame cache только в `/dev/shm`; при недоступной RAM-FS скрипт останавливается, а не пишет
  тысячи промежуточных кадров на системный диск;
- максимум четыре логических CPU через `taskset`;
- `nice 10` и `ionice -c 3` оставляют системе приоритет;
- browser GPU отключён для стабильности capture;
- финальное кодирование H.264 High quality, `CRF 16`;
- ограничения меняют время рендера, но не размер, fps, цвет, звук или encoder quality.

На Windows использовать `scripts/render-hyperframes-hidden-windows.ps1`: обычный установленный
Chrome/Edge работает headless без каскада видимых `chrome-headless-shell.exe` консолей.

Качество защищают два принципа:

1. не транскрибировать и не превьюить 12-гигабайтный мастер повторно — анализировать proxy/audio;
2. не собирать ролик через несколько последовательных lossy encode. Нормализация источника и
   delivery encode планируются заранее; дополнительный ffmpeg нужен только как осознанный этап.

Перед стартом проверить свободную RAM/диск, закрыть предыдущий renderer и убедиться, что не
остались зависшие browser workers. Одновременно запускается один финальный render job.

### Stock transition contract

- Только структурная склейка: новый тезис, доказательство, этап или layout.
- Целевая плотность — один переход на `6–10 секунд`; без смысловой границы эффект пропускается.
- Длительность `4–10 кадров` при `30 fps`, overlay-opacity максимум `70%`.
- Тайминг, frame selection и transform детерминированы.
- Исходный stock-audio исключается. Если звук несёт смысл, duck на `12–18 dB` под речь.
- Любой watermarked frame запрещён, даже один кадр на входе или выходе.

## 13. QA и приёмка

### До полного рендера

1. Запустить `npm run check` / HyperFrames strict check.
2. Снять ключевые snapshots: hook, каждый layout transition, максимальный размер лица, самый
   плотный diagram, CTA и каждый переход caption preset.
3. Собрать contact sheet и проверить на полном разрешении.
4. Прогнать anti-slop gate и source/provenance gate.
5. Проверить stock-переходы покадрово: `4–10 кадров`, alpha `≤70%`, нет watermark,
   source audio удалён или ducked, вход стоит на структурной границе.

### После рендера

- `ffprobe`: `1080×1920`, `30 fps`, SAR `1:1`, rotation `0`, ожидаемые длительность, H.264 и AAC;
- проверить начало/конец, чёрные кадры, пропавшие assets, audio sync и peak/loudness;
- создать proof-копию через `scripts/check-reels-safe-zone.*`; master не изменять;
- для TikTok создать отдельную proof-копию с
  `reference/platform-guides/ui-proof-overlays/tiktok-ui-proof-1080x1920.png`, а для
  cross-posting — с combined overlay; Instagram proof не засчитывается как TikTok QA;
- проверить критические элементы после измеренного бокового crop и возле правого action rail;
- отдельно посмотреть caption на `Y=960` или `Y=1248`, не только HTML preview;
- открыть готовый MP4 обычным плеером и проверить финальный CTA;
- для нового layout сделать тестовую приватную/черновую загрузку в целевую платформу.

Финал нельзя отдавать, если не пройден хотя бы один hard gate: реальность доказательств,
caption collision, platform crop, пропавший шрифт/логотип, рассинхрон, повторное сильное
перекодирование или неподтверждённая лицензия.

## 14. Publish, analytics и learning loop

Delivery master копируется в Downloads; готовые MP4 и тяжёлые исходники не хранятся в Git.
Публикуется одна основная CTA: блог, статья, воркшоп, подкаст или Telegram — по теме ролика.

Через `24 часа`, `72 часа` и `7 дней` заполняются:

- `content-engine/analytics/video-performance.csv`;
- `content-engine/analytics/content-experiments.csv`.

Смотреть не только views:

- viewed vs swiped, average watch/duration, completion, rewatches;
- non-follower reach, shares/reach, saves/reach;
- profile visits, follows, CTA responses;
- blog sessions, engaged sessions, article reads и downstream conversion;
- production hours на 1 000 non-follower reach и qualified blog visit.

Один залетевший ролик не становится правилом. Hook, structure, phrase, CTA или montage variant
попадает в `content-engine/winners/` только после нескольких сопоставимых публикаций. Менять в
эксперименте одну крупную переменную, остальные держать стабильными.

## 15. Как обновлять репозиторий и базу знаний

### До работы

1. Убедиться, что работа идёт внутри `reels-montage-pipeline`, а не в родительском проекте.
2. Выполнить `git status --short`, затем fetch; не перезаписывать чужие dirty changes.
3. Прочитать `AGENTS.md`, бренд-память, актуальные decisions и project brief.

### Что куда записывать

| Тип знания | Путь |
|---|---|
| Пользователь подтвердил постоянное правило | `knowledge/personal-brand-content-system.md` и профильный файл `knowledge/` |
| Платформенная геометрия/QA | `reference/platform-guides/` с датой проверки и источником |
| Сценарный голос/доказательность/CTA | `content-engine/.agents/` |
| Идея и research одного ролика | `content-engine/briefs/` |
| Тайминги и визуальная логика ролика | `videos/<slug>/STORYBOARD.md` + `storyboard.json` |
| Источники assets | `videos/<slug>/ASSET_SOURCES.md` |
| Ошибка и проверенное решение | `knowledge/05_pitfalls.md` |
| Подтверждённый результат аналитики | `content-engine/winners/` |
| Хронология и причины решений | `history/SESSION_LOG.md` / `history/DECISIONS.md` |

### Перед commit/push

1. Пересобрать generated composition проектным script.
2. Запустить check, snapshots/contact sheet и релевантный render/QA.
3. Выполнить `git diff --check` и просмотреть `git diff` глазами.
4. Stage только относящиеся к задаче файлы.
5. Не коммитить оригиналы, готовые рендеры, кэши, `.media`, секреты и авторизованные captures.
6. Commit описывает решение, а не просто «update»; push делается только после проверок.

Время сессии фиксируется по этапам: research, transcript/script, storyboard, assets/capture,
implementation, snapshots/QA, render и delivery. Рядом указывается причина долгого этапа:
скачивание официальных assets, browser capture, полная транскрипция, cold cache, повторный QA или
ограниченный low-I/O render. Это позволяет оптимизировать процесс, не снижая качество.

## 16. Инструменты, реально использованные в этой системе

| Инструмент | Роль |
|---|---|
| HyperFrames `0.8.20` | основной HTML-композитор, check, snapshots/render |
| HTML + CSS + GSAP `3.15` | канвас, типографика, детерминированная анимация |
| ffmpeg / ffprobe | import, crop/scale, нормализация звука, упаковка и технический QA |
| faster-whisper | локальная транскрипция выбранного proxy/audio |
| Python | fetch/hash/SVG safety, генерация cards/composition, нарезка |
| Browser capture | реальные публичные экраны OpenRouter и ONai Blog |
| Git/GitHub | переносимый код, briefs, знания, sources и lightweight QA |
| Remotion | запасной путь для прозрачных PNG-оверлеев и библиотека приёмов |
| fontTools | проверка кириллицы в шрифтах |
| yt-dlp | получение доступных YouTube transcripts/reference media, когда источник это разрешает |

Основная команда воспроизводимого expert Reel:

```bash
python3 scripts/fetch_brand_assets.py
bash scripts/import_source.sh /absolute/path/to/source.mov
python3 scripts/build_cards.py
python3 scripts/build_composition.py
npm run check
npm run render:low-io
```

Команды запускаются из конкретной папки `videos/<slug>/`. Перед публикацией добавляются
snapshot/contact-sheet и platform safe-zone QA.
