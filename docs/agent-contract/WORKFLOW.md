# Этапы работы над рилсом — агент сначала опрашивает, потом монтирует

Порядок для Claude Code и Codex. Каждый этап закрывается файлом в проекте, не словами в чате.
**Стоп-точки** (помечены ⏸) — агент ждёт ответа владельца и дальше не идёт.
«Владелец» — тот, кто работает с репозиторием (в правилах он же «Александр», см. `CLAUDE.md`).

## Этап 0. Модель и усилие — до первого действия

| Агент | Модель | Усилие рассуждения |
|---|---|---|
| Claude Code | Opus — самая новая (сейчас Claude Opus 5, `claude-opus-5`) | **xhigh** для режиссуры и текста, не ниже **high** на любом этапе |
| Codex | `gpt-5.6-sol` | `model_reasoning_effort = "xhigh"`, не ниже `"high"` |

- Claude Code: модель и усилие выбираются в меню модели приложения или при запуске
  (`bash scripts/session.sh director …` ставит нужное сам). Codex: `~/.codex/config.toml` → `model` и `model_reasoning_effort`.
- Агент посреди сессии уровень не меняет. Если он видит, что запущен на модели слабее Opus/`gpt-5.6-sol` или с усилием ниже
  high, — первым сообщением говорит об этом владельцу и предлагает перезапуск.
- Скептики (этап 2) запускаются на той же модели и с тем же усилием.
- Один ролик — одна сессия.

## Этап 1. Опрос ⏸

Агент задаёт вопросы **по одному**, коротко, с вариантами ответа. Не угадывает и не начинает работу, пока не заполнен бриф.

1. **О чём ролик и зачем?** Тема, для кого, что зритель должен сделать в конце (кодовое слово, подписка, переход).
2. **Текст есть?** Готовый — прислать. Нет — агент пишет (этап 2). Есть черновик — агент доводит (этап 2).
3. **Запись есть?** Путь к файлу. Если записи ещё нет — сначала текст, потом запись по нему.
4. **Какой формат монтажа?** Экспертный (с записями экрана), разговорный со вставками или подкаст —
   `knowledge/11_formats.md`, агент коротко объясняет разницу и показывает эталон.
5. **Скриншоты и материалы дашь?** Скрины результатов и просмотров, записи экрана, интерфейсы сервисов, логотипы.
   Куда положить: `videos/<проект>/assets/`. Нет — агент найдёт логотипы и интерфейсы в открытом доступе сам,
   а чисел, которых нет на скринах, не выдумывает.
6. **Референсы монтажа?** Рилсы, которые нравятся монтажом (Pinterest, сохранённые). Есть — разбор по `START.md` §6.
7. **Как сдать?** Показывать листы кадров до рендера или сразу финал; куда положить готовый файл.

Ответы — в `videos/<проект>/BRIEF.md` (агент пишет сам), итог одним сообщением владельцу: «Понял так: … Верно?» ⏸

## Этап 1b. Концепция монтажа ⏸

Сразу после опроса агент предлагает, **как ролик будет выглядеть**, и показывает примеры кадров:
`reference/style-previews/four-styles.png` картинкой в чат плюс список из `knowledge/montage-concepts.md`
(PRISM, ORBIT, TRACE, PULSE или собственный концепт под этот ролик). Владелец выбирает — выбор записывается
в `videos/<проект>/CONCEPT.md`. ⏸

Без этого файла монтаж не начинается, а рендер запрещён: агент, который сразу выдаёт «видео с субтитрами»,
пропустил этот этап.

## Этап 2. Текст рилса (если текста нет или его надо довести) ⏸

1. **Ресёрч.** Факты, цифры и названия — только из источников: сайт сервиса, документация, материалы владельца.
   Каждое утверждение — строкой в `videos/<проект>/research.md` с источником. Нет источника — нет утверждения.
2. **Черновик** по `knowledge/06_copywriting.md`: хук — обещание с разрывом любопытства (не вопрос), раскрытие по шагам,
   один призыв в конце. 2–3 варианта хука.
3. **Три скептика** — три отдельных агента (в Claude Code — субагенты, в Codex — отдельные запуски) на той же модели.
   Каждый получает **только текст и `research.md`**, без мнения автора и без других скептиков:
   - **эксперт-зритель** — целевой зритель, который в теме: понятно ли, веришь ли, где ошибка по сути, где вода;
   - **копирайтер прямого отклика** — хук, обещание, выгода, призыв: почему досмотрят и напишут кодовое слово;
   - **редактор удержания** — где отвалятся: первые 3 секунды, темп, длина фраз, новое событие каждые 3–5 секунд.

   Формат ответа каждого: оценка 1–10; три главные проблемы с цитатой из текста; конкретная правка на каждую.
4. **Сверка.** Пока скептики работают, автор сверяет каждое утверждение текста с источниками из `research.md`.
5. **Итог владельцу:** финальный текст + короткая таблица «что поменяли и почему (кто из скептиков)». ⏸
   После «да» текст — в `videos/<проект>/SCRIPT.md`; владелец записывает видео по нему.

## Этап 3. Запись и материалы

`bash scripts/new-reel.sh <проект>` → `bash scripts/prepare-media.sh videos/<проект> <запись>` (копия без кропа, речь,
пословная расшифровка). Скриншоты и записи экрана — в `assets/`, каждая строкой в `ASSET_SOURCES.md`.
Опечатки расшифровки в названиях сервисов — поправить в `transcript.json`.

## Этап 4. Монтаж

Строго по `docs/agent-contract/MONTAGE-RUNBOOK.md`: режиссура (`storyboard.json` + `DIRECTION.md` — что в кадре на каждой фразе
и почему) → сборка (`python3 scripts/pipe.py build videos/<проект>` до чистых проверок).

## Этап 5. Кадры ⏸

Лист кадров каждые 2 секунды, пронумерованный (К001, К002…), — владельцу. Правки словами и по номерам кадров:
«кадр 7 — субтитры крупнее». Решения владельца — в `history/DECISIONS.md` в том же ходе. Если владелец на этапе 1
сказал «сразу финал» — агент всё равно смотрит листы сам до рендера.

## Этап 6. Рендер и сдача

`bash scripts/render-safe.sh videos/<проект> renders/<имя>.mp4` фоном → лист кадров из самого MP4 → проверка звука →
файл владельцу туда, куда он сказал на этапе 1.

## Коротко для агента

Модель и усилие → опрос по одному вопросу → бриф ⏸ → текст: ресёрч → черновик → три скептика → сверка ⏸ →
запись и материалы → монтаж → кадры ⏸ → рендер. Ничего не ставить владельцу в терминал: ставит агент сам,
владельцу — только регистрация, оплата, ключи и разрешения.
