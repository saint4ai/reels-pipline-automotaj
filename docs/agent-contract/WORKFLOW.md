# Этапы работы над роликом — агент сначала спрашивает, потом монтирует

Порядок для Claude Code и Codex. Каждый этап закрывается файлом в проекте, не словами в чате.
**Стоп-точки** (⏸) — агент ждёт ответа владельца и дальше не идёт.
«Владелец» — тот, кто работает с репозиторием (в правилах он же «Александр», см. `CLAUDE.md`).

Стек один: **Remotion** (рендер) + **Storybook** (витрина, где каждый блок принимается отдельно) — папка `studio/`,
навык `.claude/skills/remotion-montage`. Всё идёт только через Remotion.

## Этап 0. Модель и усилие — до первого действия

| Агент | Модель | Усилие рассуждения |
|---|---|---|
| Claude Code | самая новая Opus (сейчас Claude Opus 5, `claude-opus-5`) | **xhigh** на всех этапах монтажа, не ниже **high** |
| Codex | `gpt-5.6-sol` | `model_reasoning_effort = "xhigh"`, не ниже `"high"` |

Агент посреди сессии уровень не меняет. Запущен слабее — первым сообщением говорит об этом владельцу и предлагает
перезапуск. Один ролик — одна сессия.

## Этап 1. Формат ⏸

Первый вопрос — всегда формат, картинкой `reference/style-previews/formats.jpg` прямо в чате:

> Это **рилс** (А — Instagram, Shorts, TikTok, 9:16) или **ролик для YouTube** (Б — 16:9, спикер справа)?

Ответ — в `videos/<проект>/BRIEF.md`. Формат задаёт раскладку всего ролика (`studio/src/formats.ts`), поэтому он первый.

## Этап 2. Стиль монтажа ⏸

Сразу после формата — две картинки прямо в чат: `reference/style-previews/styles.jpg` (стили 1–4) и
`reference/style-previews/more-styles.jpg` (паттерны 5–12), и вопрос:

> В каком стиле монтируем: **1 — КАНВАС**, **2 — СТЕКЛО**, **3 — ПОСТЕР**, **4 — СЦЕНЫ**, один из паттернов **5–12**
> (PRISM, ORBIT, TRACE, PULSE, экспертное стекло, портрет-квадрат, Apple depth, подкаст) или **свой стиль** под этот ролик?

Коротко объяснить, чем они отличаются и какой подходит под тему (`knowledge/montage-concepts.md`, каталог `patterns/README.md`). Выбор —
в `videos/<проект>/CONCEPT.md`. Без этого файла монтаж не начинается, рендер запрещён.

## Этап 3. Опрос ⏸

Дальше вопросы **по одному**, коротко, с вариантами ответа. Не угадывать и не начинать работу, пока бриф не заполнен.

1. **О чём ролик и зачем?** Тема, для кого, что зритель делает в конце (кодовое слово, подписка, переход).
2. **Текст есть?** Готовый — прислать. Нет — агент пишет (этап 4). Черновик — агент доводит.
3. **Запись есть?** Путь к файлу. Нет — сначала текст, потом запись по нему.
4. **Скриншоты и материалы дашь?** Результаты, записи экрана, интерфейсы, логотипы — в `videos/<проект>/assets/`.
   Нет — агент найдёт логотипы и интерфейсы в открытом доступе сам; чисел, которых нет на скринах, не выдумывает.
5. **Референсы монтажа?** Ролики, которые нравятся монтажом. Есть — разбор по `START.md` §6.
6. **Как сдать?** Показывать листы кадров до рендера или сразу финал; куда положить готовый файл.

Ответы — в `videos/<проект>/BRIEF.md`, итог одним сообщением: «Понял так: … Верно?» ⏸

## Этап 4. Текст (если текста нет или его надо довести) ⏸

1. **Ресёрч.** Факты, цифры и названия — только из источников. Каждое утверждение — строкой в `videos/<проект>/research.md`
   с источником. Нет источника — нет утверждения.
2. **Черновик** по `knowledge/06_copywriting.md` (стоп-лист штампов там же): хук — обещание с разрывом любопытства, не вопрос;
   раскрытие по шагам; один призыв в конце. 2–3 варианта хука.
3. **Три скептика** — три отдельных агента на той же модели, каждый получает **только текст и `research.md`**:
   эксперт-зритель (понятно ли, верно ли по сути, где вода), копирайтер прямого отклика (хук, выгода, призыв),
   редактор удержания (где отвалятся, темп, событие каждые 3–5 секунд). Ответ: оценка 1–10, три проблемы с цитатой, правка на каждую.
4. **Итог владельцу:** финальный текст + таблица «что поменяли и почему». ⏸ После «да» — `videos/<проект>/SCRIPT.md`.

## Этап 5. Запись и материалы

```bash
bash scripts/new-video.sh <проект> <reels|youtube> /путь/к/записи.mp4
```

Скрипт кладёт запись без кропа в `studio/public/projects/<проект>/`, делает пословную расшифровку и заготовку ролика
`studio/src/videos/<проект>/` (данные, слова, своя точка входа). Опечатки в названиях сервисов — поправить в `words.ts`.
Скриншоты и записи экрана — в `videos/<проект>/assets/`, каждая строкой в `ASSET_SOURCES.md`.

## Этап 6. Монтаж

По навыку `.claude/skills/remotion-montage`:
0. Прочитать документы выбранного стиля из `patterns/README.md` (паттерн ролика-образца, его PATTERNS и грабли) и
   просмотреть его `frames.jpg`.
1. **Карта монтажа** в `videos/<проект>/DIRECTION.md` до кода: время → фраза → фон → что на экране → стык и причина →
   размер карточки спикера. Своя под каждый ролик.
2. **Блоки** — в `studio/src/videos/<проект>/project.ts`; стиль — одной строкой в точке входа (`Template` для КАНВАСА или
   `reelOf(<СТИЛЬ>)` для 5–12), своя механика — рядом из `studio/src/kit`. Каждый новый блок —
   история в Storybook (`studio/src/stories/`), сначала принимается там.
3. **Проверки:** `npm run typecheck`, `ENTRY=… node scripts/qa-fit.mjs <проект>` → `FIT PASS`; `node scripts/qa-fit.mjs FitTest`
   обязан дать `FIT FAIL` (проверка жива).

## Этап 7. Кадры ⏸

```bash
cd studio && ENTRY=src/videos/<проект>/index.tsx node scripts/review.mjs <проект>
```

Листы кадров каждые 2 секунды с номерами К001, К002… — владельцу картинками в чат. Правки словами и по номерам:
«К007 — субтитры крупнее». Решения владельца — в `videos/<проект>/DECISIONS.md` в том же ходе. Даже если владелец сказал
«сразу финал», агент смотрит листы сам до рендера.

## Этап 8. Рендер и сдача

```bash
cd studio && npx remotion render src/videos/<проект>/index.tsx <проект> ../videos/<проект>/renders/raw.mp4
bash scripts/master.sh ../videos/<проект>/renders/raw.mp4 ../videos/<проект>/renders/final.mp4
```

Рендер — фоновой задачей. После: лист кадров из самого MP4 (ffmpeg по секундам), размер и битрейт, громкость −14 LUFS /
≤ −1 dBTP. Файл — туда, куда владелец сказал на этапе 3.

## Коротко для агента

Модель → **формат** ⏸ → **стиль** ⏸ → опрос по одному вопросу ⏸ → текст: ресёрч → черновик → три скептика ⏸ →
`new-video.sh` → карта монтажа → блоки и Storybook → qa-fit → кадры ⏸ → рендер → мастеринг → сдача.
Ничего не ставить владельцу в терминал: ставит агент сам, владельцу — только регистрация, оплата, ключи и разрешения.
