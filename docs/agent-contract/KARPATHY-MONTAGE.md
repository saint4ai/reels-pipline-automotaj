# Правила Карпати для монтажа — как организована работа агента

Источник: `.claude/skills/karpathy-guidelines/SKILL.md` (Karpathy-inspired guidelines). Здесь — перевод четырёх правил
на монтаж рилса и на правки пайплайна. Замеры — по транскриптам сессий 1–3 сентября 2026 (§5).

## 1. Думать до монтажа (Think Before Coding)

- Перед сторибордом агент пишет в `DIRECTION.md` три абзаца: тезис ролика, какие сцены и почему, какие допущения
  (формат исходников, состояния спикера, где CTA). Допущение, которое меняет результат, задаётся Александру
  вопросом до сборки; список вопросов ≤ 5, остальное решается по `history/DECISIONS.md` без вопросов.
- Если есть два прочтения замечания Александра («апскейл» = рендер или нейросеть), названы оба и выбран простой.
- Непонятно — стоп и вопрос, а не сборка «на всякий случай». Одна сборка стоит 65–100k экв.

## 2. Минимум (Simplicity First)

- Ролик = один `storyboard.json` + библиотека `parts/` эталона. Новый вид сцены или объекта пишется только если
  в библиотеке его нет и он нужен произнесённому слову. Никаких новых шрифтов, эффектов, скриптов «про запас».
- Без субагентов. Один-два — только ради независимого суждения (ревью кадров), с файлом и вопросом, не с репозиторием.
  Замер: 34 субагента сессии Opus = 9.4 млн экв., 0 роликов.
- Документы пишутся один раз в конце фазы, не после каждого шага (выход ×5 — вторая статья расхода).

## 3. Хирургические правки (Surgical Changes)

- Правится только сториборд и `parts/` своего проекта. `index.html` — продукт сборщика, руками не трогать.
  Сборщик и валидатор правятся только когда правило Александра нельзя выразить сторибордом, и правка одна.
- Медиа перекодируются один раз при подготовке; повторно — только если проверка требует (GOP, кроп, скорость).
- Чужие проекты, чужие сессии, чужие файлы не трогать; провенанс-хеш это контролирует. Один проект — один агент.
- Каждая правка отслеживается до слова Александра или до ошибки проверки. Коммит — в конце фазы, с понятным текстом.

## 4. Цель с проверкой, цикл до подтверждения (Goal-Driven Execution)

Ворота фаз, каждое проверяемо командой или листом кадров:

| Фаза | Критерий готовности | Чем проверяется |
|---|---|---|
| Подготовка | все исходники в `ASSET_SOURCES.md`, медиа без кропа, GOP 30 | `ffprobe`, `pipe.py state` |
| Режиссура | `validate` BLOCKING 0; смены спикера ≤ 10 с; рукописная вставка ≥ каждой второй сцены | `pipe.py validate`, `plan --layout` |
| Сборка | `check` 0 ошибок; лист снимков каждые 2 с без наложений и обрезанных границ | `pipe.py build`, `snapshot`, глаза |
| Рендер | `render-safe` OK, QA PASS; лист 20 кадров MP4 чистый | `render-safe.sh`, `ffmpeg tile` |
| Сдача | файл у Александра, журнал, DECISIONS, коммит | `git log` |

Слабый критерий («сделай красиво») запрещён: он превращается в переписку. Замечание по кадру → правило в базу
знаний → правка → тот же цикл проверки заново.

## 5. Бюджеты токенов по фазам (экв. = вход + кэш-чт×0.1 + кэш-зап×1.25 + выход×5)

| Фаза | Ходов | Бюджет экв. | Контекст сессии |
|---|---|---|---|
| Режиссура (director) | ≤ 25 | ≤ 1.0 млн | свежая, ≤ 150k |
| Сборка и снимки (build) | ≤ 40 | ≤ 2.0 млн | свежая, ≤ 120k |
| Ревью правок Александра (review) | ≤ 20 | ≤ 0.8 млн | ≤ 100k |
| Итого на ролик | ≤ 85 | ≤ 4 млн | три сессии, не одна |

Факты, из которых бюджеты: монтаж v2→v4 этого ролика — 82 хода, 5.2 млн при контексте 400k/ход; та же работа в
свежей сессии ≤ 150k стоила бы ~2 млн. Один ход дороже байтов: 80–90 % цены хода — повторное чтение контекста.
Батчить независимые вызовы, смотреть листы, а не кадры, не читать файлы целиком, не опрашивать рендер в цикле.
