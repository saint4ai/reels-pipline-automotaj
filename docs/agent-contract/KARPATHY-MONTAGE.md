# Правила Карпати для монтажа — как организована работа агента

Источник: `.claude/skills/karpathy-guidelines/SKILL.md` (Karpathy-inspired guidelines). Здесь — четыре правила применительно
к монтажу на студии Remotion.

## 1. Думать до монтажа (Think Before Coding)

- До кода агент пишет в `videos/<проект>/DIRECTION.md` карту монтажа: тезис ролика, смысловые блоки и механика каждого,
  стыки и их причина, допущения. Допущение, которое меняет результат, задаётся владельцу вопросом до сборки; вопросов ≤ 5.
- Если у замечания владельца два прочтения — назвать оба и выбрать простое.
- Непонятно — стоп и вопрос, а не сборка «на всякий случай».

## 2. Минимум (Simplicity First)

- Ролик = данные блоков (`studio/src/videos/<проект>/project.ts`) + стиль или шаблон + свои сцены только там, где их нет
  в библиотеке и они нужны произнесённому слову. Никаких новых шрифтов, эффектов и скриптов «про запас».
- Без веера субагентов. Один-два — только ради независимого суждения (скептики текста), с файлом и вопросом.
- Документы пишутся один раз в конце фазы, не после каждого шага.

## 3. Хирургические правки (Surgical Changes)

- Правится только код своего ролика в `studio/src/videos/<проект>/`. Общие `kit`, `styles`, `template` меняются, только
  если правило владельца нельзя выразить в своём ролике, и правка одна; старые ролики после неё проверяются.
- Медиа перекодируются один раз при подготовке (`new-video.sh`).
- Чужие проекты и сессии не трогать. Один ролик — один агент.

## 4. Цель с проверкой (Goal-Driven Execution)

| Фаза | Критерий готовности | Чем проверяется |
|---|---|---|
| Подготовка | запись без кропа, расшифровка поправлена, исходники в `ASSET_SOURCES.md` | `ffprobe`, `words.ts` |
| Режиссура | карта монтажа: у каждого блока механика и причина стыка; ≥ 4 механики на минуту | `DIRECTION.md` |
| Сборка | типы сходятся, `FIT PASS`, `FitTest` падает; блоки приняты в Storybook | `npm run typecheck`, `qa-fit.mjs` |
| Кадры | листы каждые 2 с без наложений, пустых стыков и обрезанного текста; «да» владельца | `review.mjs`, глаза |
| Рендер | MP4 есть, лист из самого файла чистый, −14 LUFS / ≤ −1 dBTP, битрейт замерен | `master.sh`, `ffprobe` |

Слабый критерий («сделай красиво») запрещён. Замечание по кадру → правка → тот же цикл проверки заново.

## 5. Экономия

Свежая сессия на ролик, контекст ≤ 150k. Батчить независимые вызовы, смотреть листы, а не кадры, не читать файлы целиком,
не опрашивать рендер в цикле — рендер идёт фоновой задачей.
