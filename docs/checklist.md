# Чек-лист внедрения

Семь шагов, отсортированных по соотношению выгоды к усилию. Первые три занимают вечер,
остальные — отдельная работа.

## 1. Померьте, прежде чем оптимизировать

Пока нет чисел, любая оптимизация — угадывание. Мы дважды ошиблись именно так.

Найдите транскрипты своего агента и сложите расход по категориям. Для Claude Code это
`~/.claude/projects/<путь-проекта>/*.jsonl`, для Codex — `~/.codex/sessions/<год>/<месяц>/`.
В записях есть поле `usage` с четырьмя счётчиками.

```python
import json, glob
t = {'in': 0, 'out': 0, 'cr': 0, 'cw': 0, 'turns': 0}
for f in glob.glob('<путь>/**/*.jsonl', recursive=True):
    for line in open(f, encoding='utf-8', errors='ignore'):
        if '"usage"' not in line:
            continue
        try:
            r = json.loads(line)
        except Exception:
            continue
        m = r.get('message')
        u = m.get('usage') if isinstance(m, dict) else r.get('usage')
        if not isinstance(u, dict):
            continue
        t['in'] += u.get('input_tokens', 0)
        t['out'] += u.get('output_tokens', 0)
        t['cr'] += u.get('cache_read_input_tokens', 0)
        t['cw'] += u.get('cache_creation_input_tokens', 0)
        t['turns'] += 1
print(t, 'эквивалент:', t['in'] + t['cr']*0.1 + t['cw']*1.25 + t['out']*5)
```

Отдельно посчитайте субагентов — у них своя директория, и обычно именно там сидит основной
расход.

## 2. Проверьте, обрезает ли ваш инструмент вывод команд

Это решает, нужна ли вам обёртка вокруг долгих процессов.

Запустите команду, печатающую заведомо много, и посмотрите, что дошло до модели:

```bash
seq 1 200000 | awk '{print "строка", $1, "заполнитель заполнитель заполнитель"}'
```

Если инструмент сохранил вывод в файл и показал превью — механизм защиты есть, и логи
не ваша главная проблема. Если весь текст оказался в разговоре — обёртка обязательна,
и она даст вам больше, чем всё остальное в этом списке.

## 3. Тихий режим и fail-fast для каждой долгой команды

Найдите у своих инструментов флаг подавления вывода: `--quiet`, `--silent`, `-q`,
`--log-level=error`. Заведите обёртку по образцу
рендер Remotion фоновой задачей, в чат — только итог (`studio/scripts/master.sh` печатает размер, битрейт и громкость):

- полный вывод в `logs/`, не на экран;
- `grep` по критическим шаблонам сразу после завершения;
- на экран — код возврата, первые несколько критических строк, счётчик предупреждений.

Разница на нашем проекте: 108 317 байт против 848.

## 4. Проекции вместо чтения

Для каждого крупного артефакта, который агент открывает регулярно, напишите команду,
отвечающую на вопрос вместо выдачи файла.

Хороший признак проекции: она отвечает на вопрос, который агент задаёт чаще всего,
и честно называет то, что не показала.

Начните с одного файла — того, который открывается в каждой сессии. Обычно этого хватает,
чтобы окупить усилие.

## 5. Байтовый потолок и явная обрезка

Каждая команда получает лимит. При превышении — маркер с числом выброшенного и способом
достать остальное. Реализация занимает пятнадцать строк:

```python
def emit(lines, cap=3000, more=""):
    out = "\n".join(lines)
    raw = out.encode("utf-8")
    if len(raw) <= cap:
        print(out)
        return
    keep = raw[:cap].decode("utf-8", "ignore").rsplit("\n", 1)[0]
    dropped = len(lines) - keep.count("\n") - 1
    print(keep)
    print(f"[ОБРЕЗАНО: ещё {dropped} строк, {len(raw)-cap} байт. Полностью: {more}]")
```

## 6. Входная дверь для агента

Маленький файл, который читается первым и запрещает читать остальное. Шаблон —
[`CONTEXT.md`](../CONTEXT.md). Держите его в пределах 3–5 КБ, иначе он сам станет проблемой.

Что в нём должно быть: список команд-проекций, три закона фильтрации, явный перечень
«по умолчанию не делать» и указание на файлы, которые нельзя ломать.

Важная оговорка из нашего опыта: **текст политики не является механизмом.** Мы дважды
за вечер написали агентам жирный запрет запускать рендер — оба раза они его запустили.
Работает только механика: отсутствующий флаг, обёртка без прав, тихий режим по умолчанию.
Политику пишите как документацию решения, а защиту стройте в коде.

## 7. Дисциплина сессий и агентов

Два правила, которые ничего не стоят:

**Не запускайте веера субагентов без крайней необходимости.** Это единственная статья
расхода своего порядка. Два-три агента, и только ради независимости суждения.

**Разделяйте режимы.** Production-сессия читает бриф и одну сцену, делает точечную правку
и останавливается. Research-сессия читает полную базу знаний. Смешивать их в одной сессии
дорого: ранний контекст переносится до конца и оплачивается каждый ход.

## Чего делать не надо

**Удалять документацию и скиллы ради экономии контекста.** Проверьте сначала, резидентны
ли они. У нас оказалось, что из 1912 КБ скиллов постоянно висит только фронтматтер —
около 2000 токенов. Удаление не дало бы ничего, а потери были бы реальными.

**Складывать размеры файлов и называть сумму расходом.** Это гипотеза о худшем случае.
Реальный расход виден только в транскриптах.

**Менять инструмент, не разобравшись в причине.** Смена движка или редактора не трогает
ни веера агентов, ни выходные токены, ни длину сессии — то есть ни один из настоящих
драйверов расхода.
